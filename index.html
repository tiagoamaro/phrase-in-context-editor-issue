Phrase In-Context Editor vs Tailwind hidden lg:block

Viewport must be ≥1024px wide (Tailwind lg breakpoint) for this repro to demonstrate the bug. Below 1024px all three boxes are correctly hidden or shown per their classes, and there is nothing to see.

Load with ?phrase=on to arm the editor. Add &hidingClasses=off to also drop "hidden" from the scanner's hidingClasses config (per ngx-translate-phraseapp#63) — expected to have no effect, since that option isn't what drives this skip.

1. Control — plain visible div

No hiding classes at all. Phrase must wrap this marker. If it doesn't, the integration itself is broken — not the bug under test.

{{phrase_repro.control}}

2. Victim — hidden lg:block

Genuinely visible at this viewport (≥1024px) because lg:block overrides hidden. Phrase's scanner sees the literal hidden class token and skips the subtree regardless — this is the bug.

{{phrase_repro.victim}}

3. Expected-hidden — bare hidden, no override

Correctly hidden at every viewport, no responsive override. Phrase is supposed to skip this one — included so the claim stays scoped to "computed visibility vs. class-token presence", not "hidden should always be scanned".
